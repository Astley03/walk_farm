## 1. 專案背景與目標

### 1.1 開發背景

田邊走走目前主要透過 LINE 官方帳號提供住宿資訊、訂房諮詢、餐飲代訂及合作廠商介紹。

由於資訊種類較多，使用者需要在 LINE 訊息中尋找房型照片、餐飲菜單、合作資訊及入住須知，查詢較不方便。

因此希望建立一個以資訊展示為主的官方網站，協助旅客快速找到需要的內容。

### 1.2 開發目標

1. 集中展示民宿 A、B 館房型與照片。
2. 提供獨立的住宿訂房網站入口。
3. 整理烤肉、火鍋、代烤等餐飲資訊。
4. 提供宜蘭縣食、玩、樂景點推薦與互動地圖。
5. 展示農場優惠與接送、包車等合作服務。
6. 提供完整住宿須知及聯絡資訊。
7. 支援手機與電腦瀏覽。
8. 減少旅客重複詢問基本資訊的需求。

### 1.3 網站定位

網站屬於「民宿資訊展示與服務導覽平台」，不建立線上付款、訂單管理或即時訂房系統。

**網站不另外顯示任何服務價格。** 餐飲廠商原始菜單圖片中的價格可以保留，實際房價與空房查詢交由外部訂房網站處理。

## 2. 網站整體架構

### 2.1 主要選單

| 選單名稱 | 主要內容 |
|---|---|
| 首頁 | 民宿形象照片、介紹、快捷入口 |
| 房型介紹 | A 館、B 館選擇及詳細介紹 |
| 餐飲服務 | 代訂食材、代訂火鍋、代烤服務 |
| 周邊探索 | 食、玩、樂分類與互動地圖 |
| 合作廠商 | 合作農場、接送與包車 |
| 民宿選物 | 敬請期待 |
| 入住須知 | 完整住宿規定 |
| 位置與交通 | A、B 館地址與導航 |

另提供醒目的「立即訂房」與「官方 LINE」入口。

### 2.2 頁面實作方式

採用單一 HTML 的多區塊網站架構。

首頁顯示主要介紹與選單；房型詳細介紹、民宿選物等內容可透過 JavaScript 實現頁面切換效果，但不建立額外 HTML 檔案。

網站所有功能整合在同一個 `index.html` 中。

## 3. 視覺與介面設計

### 3.1 整體風格

以田邊走走的白色簡約建築為設計核心。

- 主色：白色、米白色。
- 輔助色：淺灰、自然綠、柔和大地色。
- 設計方向：現代簡約、自然、明亮、舒適。
- 使用大量真實民宿照片。
- 減少不必要的裝飾。
- 使用清楚、易讀的繁體中文字體。

### 3.2 首頁設計

首頁包含：

1. 網站頂部導覽列與民宿名稱。
2. 民宿形象大圖。
3. 簡短品牌介紹。
4. 「查看房型」與「立即訂房」快捷入口。
5. A、B 館簡要介紹。
6. 餐飲、周邊探索、合作服務的入口。
7. 頁尾地址、電話、LINE 與導航資訊。

### 3.3 響應式設計

網站需同時支援電腦、平板及手機。

電腦版使用橫向導覽、寬版照片與卡片配置；手機版改為適合觸控的選單與單欄式排列。

圖片需依畫面大小自動調整，避免跑版。

## 5. 餐飲服務功能

### 5.1 分類

餐飲服務分為以下三類：

1. 代訂食材
2. 代訂火鍋
3. 代烤服務

分類名稱與上傳素材保持一致。

### 5.2 內容展示

使用者可選擇餐飲分類，瀏覽對應的廠商菜單及服務照片。

- 每個分類展示多張圖片。
- 圖片可點擊放大查看。
- 保留菜單圖片原有的廠商名稱、套餐內容及價格。
- 網頁本身不重複建立商品或價格表。
- 不提供購物車及線上結帳功能。

### 5.3 訂購方式

提供兩種訂購途徑。

**方式一：自行向廠商訂購**

1. 查看廠商及套餐圖片。
2. 查詢廠商聯絡方式。
3. 向廠商訂購，並告知配送至田邊走走 A 館或 B 館。
4. 訂購成功後，將資訊回傳官方 LINE。

**方式二：委託民宿代訂**

1. 查看餐飲方案圖片。
2. 決定廠商與套餐。
3. 複製餐飲詢問範本。
4. 傳送至田邊走走官方 LINE，由民宿協助確認。

### 5.4 LINE 訂購資訊範本

提供「複製訊息」功能，內容如下：

田邊走走｜餐飲訂購／回報

廠商名稱：

套餐內容：

送達日期：

入住館別：A 館／B 館

訂購方式：自行訂購／民宿代訂

使用者自行填入資料後，可複製並貼到官方 LINE。

### 5.5 注意事項

- 餐飲服務請提前 3～7 天預訂。
- 訂購成功後，廠商於預定日期配送至民宿。
- 管家協助代收。
- 民宿提供烤肉爐，但不提供木炭、烤肉網、夾子等用品。
- 餐飲訂購與實際方案內容，以廠商及民宿確認為準。

## 6. 周邊探索與互動地圖

### 6.1 功能目標

讓旅客可以快速了解宜蘭縣值得造訪的景點，並透過地圖比較各景點與住宿館別的相對位置。

### 6.2 景點分類

| 分類 | 內容 |
|---|---|
| 食 | 在地餐廳、小吃、咖啡廳、美食 |
| 玩 | 自然景點、親子景點、農場、觀光景點 |
| 樂 | 體驗活動、娛樂設施、特色行程 |

### 6.3 地圖互動功能

- 顯示田邊走走 A、B 館位置。
- 使用不同圖示區分民宿與景點。
- 提供「食、玩、樂」分類選擇。
- 選擇分類後，地圖只顯示該類景點及兩館位置。
- 點擊地圖標記可看到景點名稱及介紹。
- 可開啟 Google Maps 查看景點或導航。
- 支援放大、縮小及拖曳地圖。

### 6.4 景點詳細內容

每個推薦景點原則上提供：

- 景點名稱
- 景點照片
- 簡短特色介紹
- 推薦玩法或活動
- 所在區域
- Google Maps 導航入口

第一版可使用精選宜蘭熱門景點，之後再持續增加。

### 6.5 技術規劃

優先使用 Leaflet 搭配 OpenStreetMap 圖資實現地圖功能。

地圖標記和景點介紹資料由 JavaScript 管理。

需依實際地址核對 A、B 館與景點的座標，不得使用猜測位置。

第一版以景點顯示、分類篩選與導航為主；距離與行程規劃僅在有可靠路線資料時提供。

自動安排最佳旅遊路線及 AI 智慧推薦暫不列入第一版。

## 13. 技術開發規格

### 13.1 使用技術

- HTML5：網站結構。
- CSS3：版面、色彩、排版與響應式設計。
- JavaScript：切換頁面、圖片相簿、複製文字及地圖互動。
- Leaflet：互動地圖。
- OpenStreetMap：地圖圖資。
- GitHub Pages：網站公開部署。

### 13.2 單檔案限制

最終交付一個 `index.html`。

CSS 使用 HTML 中的 `<style>`。

JavaScript 使用 HTML 中的 `<script>`。

照片以適當的嵌入方式整合至 HTML，避免部署時依賴額外圖片檔案。地圖圖資等外部網路服務則可透過網路載入。

### 13.3 效能要求

- 圖片載入需兼顧畫質與檔案大小。
- 縮圖和詳細大圖可使用不同解析度。
- 避免一次解碼大量高解析度照片。
- 支援常見桌面與手機瀏覽器。
- 在 GitHub Pages 環境正常運作。

### 13.4 無後端系統

第一版不使用：

- 資料庫。
- 使用者登入。
- 訂房後台。
- 金流服務。
- 購物車。
- AI 行程規劃 API。

## 開發過程與需求調整
本專案最初依照規格書 V1.0 進行開發。

在實際測試過程中，原本規劃使用
OpenStreetMap 顯示周邊景點，
但因圖資載入限制與顯示問題，
後續改為插畫式互動導覽地圖。

此調整保留了景點分類、
民宿位置標記及 Google Maps 導航功能，
同時改善網站的視覺風格與使用體驗。

另外，開發過程中也持續調整
餐飲訂購說明、響應式版面，
並新增回頂端按鈕等操作功能。
